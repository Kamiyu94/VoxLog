🍎 macOS 安裝指南

Mac 版沒有「雙擊一個檔案」那麼自動,需要在「終端機」貼幾行指令。別緊張 —— 每段都有複製鈕,照順序貼上、按 Enter 就好。整個流程約 5 個步驟。

⌨️ 怎麼打開「終端機」?按 ⌘ Command+空白鍵 叫出 Spotlight,輸入 Terminal 或 終端機,按 Enter。之後的指令都貼進這個黑視窗。

❓ 為什麼 Mac 比 Windows 麻煩?VoxLog 原本是在 Windows 上開發的,搬到 Mac 會撞到「系統內建 Python 太舊讓程式閃退」「新版 macOS 跟某些 AI 套件不合」等問題。下面步驟已經幫你避開大部分的坑;只有第一次安裝會遇到,裝好就一勞永逸。

1安裝 Homebrew(套件管家)

Homebrew 是 Mac 上幫你裝軟體的工具。先確認有沒有裝過 —— 在終端機貼這行:

brew --version

有跳出版本號(例如 Homebrew 4.x)→ 你已經裝過,直接跳到步驟 2。
顯示「command not found」→ 貼下面這行安裝(會問你密碼,輸入時看不到字是正常的):

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
⏳安裝中途會停住、游標不動好幾分鐘(在下載開發者工具),這是正常的,別關。若彈出一個小視窗問要不要裝「命令列工具」,按 Install 等它跑完。

接著一定要做這步:讓系統認得 brew

裝完先別急著下一步。Homebrew 雖然裝好了,但系統還不知道去哪找它,這時候打 brew 會說「找不到」。把下面這一整段複製貼上、按 Enter,就接上了(不會有任何訊息是正常的):

echo >> ~/.zprofile
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

然後再貼一次 brew --version 驗證 —— 這次有跳出版本號(例如 Homebrew 5.x)就成功了,可以往步驟 2。以後開新終端機都會自動生效,不用再貼。

❗ 為什麼要這一步?這是 Apple Silicon(M1/M2/M3… 晶片)Mac 最常卡住的地方:brew 明明裝好了,打 brew --version 卻說「command not found」。原因就是上面這段沒做 —— 它的作用是把 brew 的位置加進系統的搜尋名單。貼完上面那段就能解決。

2裝 Python 與 FFmpeg

一行指令裝齊三樣東西:正確版本的 Python、它的圖形介面元件、以及處理音訊的 FFmpeg。

brew install python@3.11 python-tk@3.11 ffmpeg
❗ 為什麼指定 3.11?Mac 系統內建的 Python 是舊版,直接拿來跑 VoxLog 的圖形介面會一開就閃退。所以一定要用 Homebrew 這個 python@3.11,後面建環境時也要用它。
⏳FFmpeg 有點大,這步可能要等一兩分鐘,屬正常。

3下載專案

最簡單(免裝 git):

打開 GitHub 專案頁 → 綠色 <> Code 按鈕 → Download ZIP → 在「下載項目」裡雙擊解壓縮,把 VoxLog 資料夾拖到你想放的地方(例如「文件」)。

📁記住這個 VoxLog 資料夾放哪、別把裡面的檔案拆開搬。整包要待在一起。

(進階)有裝 git 的話:

git clone https://github.com/Kamiyu94/VoxLog.git

4建立環境並啟動

先用終端機進到 VoxLog 資料夾。最省事的方法:在終端機輸入 cd 加一個空格,然後把 VoxLog 資料夾從 Finder 拖進終端機視窗(會自動填路徑),再按 Enter。

cd

(上面複製到的是 cd 加空格;貼上後拖資料夾進來再按 Enter。)

進到資料夾後,把這一整段複製、貼上、按 Enter。它會建立獨立環境、下載所有需要的套件、設定好 voxlog 快速啟動指令、然後打開 VoxLog:

/opt/homebrew/bin/python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
chmod +x voxlog
ln -sf "$PWD/voxlog" /opt/homebrew/bin/voxlog
python transcribe_gui.py
⏳ 第一次會很久它要下載 約 2GB 的 AI 語音模型套件,網路要穩、請耐心等(可能 10 分鐘以上)。畫面停著在跑文字不是當機,是在下載,中途別關。
⭐ 以後開 VoxLog 超簡單上面那段已經幫你設好 voxlog 指令了。以後在任何地方打開終端機,只要打一個字: 
voxlog

就會自動進資料夾、啟用環境、開啟 App,不用重裝、不用 cd。
(若哪天 voxlog 沒反應,也可手動:cd 進資料夾後貼 source venv/bin/activate 再 python transcribe_gui.py。)

😵 如果這步「程式一閃就關」或出現一堆紅字多半是撞到 Mac 的已知坑。往下看 ⚠️ 疑難排解,對照 ①②③ 解決。

5填 API Key 開始用

程式打開後會自動建立設定檔,你不用碰任何檔案。在介面上:

① 選 AI 引擎(ChatGPT / Gemini / Claude)
② 在 Key 欄位貼上 API Key(跟 Kris 拿,或照下面自己申請)
③ 按 「驗證」,變綠就成功(會自動存檔)
④ 載入音檔或 .md / 逐字稿 → 開始轉錄、校正、產生摘要

怎麼自己申請 Gemini API Key(免費)

Gemini 有免費額度,個人用通常夠。三步:

① 用 Google 帳號登入 Google AI Studio 金鑰頁(網址:aistudio.google.com/apikey)
② 按 Create API key → 選一個專案(沒有就讓它自動建)
③ 產生後按 Copy 複製那串 key,貼進 VoxLog 的 Key 欄位按驗證

❗ 一定要從這個網址拿要的是 Google AI Studio 的 API Key —— 開頭是 AIza 或 AQ. 都正常(AQ. 是 2026 的新格式)。不要拿成 Google Cloud Console「憑證」裡的 OAuth(ya29./GOCSPX-),那種驗證會出現 401 ... Expected OAuth 2 access token 的錯誤。
📋 複製後想先確認 key 是好的?把網址 https://generativelanguage.googleapis.com/v1beta/models?key=你的KEY 的「你的KEY」換掉,貼到瀏覽器按 Enter —— 跳出一堆模型清單就是有效。
貼進 VoxLog 後若驗證仍失敗,多半是貼上時沒貼完整:點欄位 → 把舊內容整個刪乾淨 → 重新貼一次。

(想用 ChatGPT 或 Claude 的話,key 分別在 platform.openai.com/api-keys、console.anthropic.com 申請,作法類似。)

✓ 完成! 之後每次要用,在終端機打一個字 voxlog 就能開,不必再重裝。

🔄之後怎麼更新到最新版

VoxLog 有改版時,用 git 一行就能更新,不會動到你的 API Key 與已裝好的環境。

① 先確認有沒有 git

git --version

有跳出版本號 → 已內建(裝 Homebrew 時通常會一起裝),跳到 ②。
顯示沒有 → 貼這行裝它:

brew install git

② 第一次:把資料夾接上 git(只做一次)

如果你當初是用「Download ZIP」下載的,先進到 VoxLog 資料夾(cd + 拖資料夾),貼這一整段把它接到線上專案:

git init
git remote add origin https://github.com/Kamiyu94/VoxLog.git
git fetch origin
git reset --hard origin/main
git branch -M main
🔒你的 config.json(API Key)和 venv(已下載約 2GB 的環境)都不會被覆蓋,放心。
(當初是用 git clone 下載的人不用做這步。)

③ 以後每次更新

進到 VoxLog 資料夾,貼:

git pull

接著啟用環境、補裝可能新增的套件(這步很快,沒新套件也不會有壞處):

source venv/bin/activate
pip install -r requirements.txt

更新完打 voxlog 重開 App 即可。

✨ 這次更新有什麼新東西?
  • 貼 API Key 不再出錯:Key 欄位現在「貼上=整段取代並自動去除前後空白」,不會再把舊殘值黏成壞字串(之前 Gemini 一直 401 的元兇)。直接在 App 裡貼 Key 就會通,不用再手動編 config.json。
  • 完成後自動開檔:逐字稿、AI 校正、摘要做完會自動用系統預設程式打開給你看,不用自己去資料夾找。
  • 摘要改成 Word 檔(.docx):「產生摘要」現在直接輸出 _摘要.docx,Word / Pages 直接開,標題、清單、待辦表格都排好。
  • 低階機器更穩:預設轉錄模型改為較省記憶體的 small,8GB 的 Mac 不會一跑就閃退(要更高精度再手動選 medium/large)。

⚠️ 因為這次新增了產生 Word 檔的套件,更新後請務必跑上面那行 pip install -r requirements.txt,否則「產生摘要」會失敗。

⚠遇到問題?(疑難排解)

下面幾個是搬到 Mac 第一次安裝才會踩的坑。沒遇到就不用理它;遇到了再對照症狀展開來看。

① 程式一開就閃退 / SIGABRT最常見

症狀:執行最後一行後,視窗一閃就消失,或報 EXC_CRASH / SIGABRT。

原因:用到了 Mac 系統內建的舊 Python(連到太舊的繪圖元件 Tcl/Tk)。

解法:確認步驟 4 的第一行是用 /opt/homebrew/bin/python3.11 來建環境(不是只打 python3)。若先前建錯了,刪掉重來:

rm -rf venv
/opt/homebrew/bin/python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python transcribe_gui.py
② 連環境都建不起來(pyexpat 符號錯誤)看版本

症狀:python3.11 -m venv 失敗,或紅字出現 Symbol not found: _XML_SetAllocTrackerActivationThreshold。

原因:Homebrew 的 Python 內某個模組連到 Mac 系統舊版的 expat 函式庫,缺了新符號。

解法:裝 Homebrew 版 expat,把該模組改指向它再重新簽章:

brew install expat
SO=$(ls /opt/homebrew/Cellar/python@3.11/*/Frameworks/Python.framework/Versions/3.11/lib/python3.11/lib-dynload/pyexpat.cpython-311-darwin.so | head -1)
install_name_tool -change /usr/lib/libexpat.1.dylib /opt/homebrew/opt/expat/lib/libexpat.1.dylib "$SO"
codesign --force --sign - "$SO"
/opt/homebrew/bin/python3.11 -c "import pyexpat; print('pyexpat OK')"

看到 pyexpat OK 就修好了,回去重做步驟 4。
⚠️ 日後 brew upgrade 或重裝 python@3.11 後可能要重跑這段一次。

③ 語者分離壞掉(torchcodec 找不到 libavutil)選用

症狀:跑「語者分離」時報 libtorchcodec... Library not loaded: @rpath/libavutil.59.dylib。(一般轉錄不受影響,只有要分辨不同講者時才會壞。)

原因:系統 FFmpeg 是 8.x,但負責讀音訊的 torchcodec 只吃 FFmpeg 7。

解法:另外裝 ffmpeg@7(不影響你現有的 FFmpeg 8),把它的函式庫接到 torchcodec 會找的位置:

brew install ffmpeg@7
cd /opt/homebrew/lib
for lib in libavutil.59 libavcodec.61 libavformat.61 libavdevice.61 \
           libavfilter.10 libswscale.8 libswresample.5; do
  ln -sf "/opt/homebrew/opt/ffmpeg@7/lib/$lib.dylib" "$lib.dylib"
done

之後若看到 objc[...] Class AVFFrameReceiver is implemented in both... 的黃字警告可忽略,不影響 VoxLog。

④ 語者分離要怎麼拿 HuggingFace Token?選用

只有要用「分辨不同講者」(WhisperX 引擎的語者分離)時才需要,而且 Token 免費。一般轉錄、做摘要都不用。三步:

① 註冊 / 登入並產生 Token
到 huggingface.co/settings/tokens 註冊(或登入)→ 按 Create new token → 名稱隨意,務必勾選 Read access to public gated repositories → 建立後把那串 token 複製起來(只會顯示一次)。

② 用同一個帳號到下面兩頁按「同意」
各自進去後點 Agree and access repository:
• pyannote/speaker-diarization-community-1
• pyannote/segmentation-3.0

③ 貼進 VoxLog
打開 App,在「HuggingFace Token」欄位貼上剛剛複製的 token(會自動存進 config.json 的 hf_token)。

❗ 一定要同意 community-1 那頁VoxLog 實際用的是 speaker-diarization-community-1 這個模型。如果填了 token 卻還是失敗,多半是只同意了舊版 3.1、漏了 community-1 —— 回去把上面兩頁都按過同意即可。
⑤ AI 的 API Key 驗證失敗 / 401 錯誤最常見

症狀:在 Key 欄位貼上後按「驗證」,出現紅字 HTTP 401: ... Expected OAuth 2 access token ...,或一直不會變綠。

原因 1:拿錯 key。Gemini 的 API Key 兩種開頭都合法:AIza(舊格式)或 AQ.(2026 新格式,部分帳號只發這種,屬正常,VoxLog 也支援)。但如果你的 key 是 ya29.、GOCSPX-、4/ 開頭,那不是 API Key(分別是 OAuth token / 用戶端密鑰 / 授權碼),複製錯地方了。一律到 aistudio.google.com/apikey 拿(沒有就按 Create API key)。

❗「瀏覽器跑出東西」不等於 key 是好的把 key 貼到測試網址後,壞 key 一樣會回一段 JSON,只是內容是錯誤。要看跑出來的是哪種:
• 一條條 "models/gemini-..." 的清單 → key 好
• 開頭是 "error"、有 "API key not valid" 或 code: 400/401/403 → key 壞(換一把)

測試網址(把「你的KEY」換掉,貼瀏覽器按 Enter):

https://generativelanguage.googleapis.com/v1beta/models?key=你的KEY

原因 2:key 沒貼乾淨(舊版才會遇到)。Key 欄位用 * 星號遮住,看不到內容;舊版若欄位裡有殘缺的舊 key、又沒清掉就貼,新 key 會接在後面變成一長串壞東西。新版已修正:在 Key 欄位貼上時會自動「整段取代+去除前後空白」,直接貼就會通。所以先照「🔄 之後怎麼更新到最新版」更新一次,多半就解決了。萬一還在舊版,手動解:點進欄位 → 整個刪乾淨(按住 Delete 刪到空)→ 再貼一次乾淨的 key。

🛟 終極解法:直接寫進設定檔,完全繞過輸入框如果上面都試了還是失敗,在 VoxLog 資料夾內開設定檔: 
open -e config.json
把 "gemini_key": "..." 引號中間整段換成確認過的 AIza key(其他引擎是 anthropic_key / openai_key),存檔(⌘S)→ 重開 voxlog。App 會自動把它載進欄位,不必再經過複製貼上。
⑥ App 裡複製貼上(⌘C / ⌘V)沒反應macOS

症狀:在 VoxLog 視窗裡 ⌘C / ⌘V / ⌘A 沒作用,key 或網址貼不進去。

原因:macOS 上 tkinter(VoxLog 的介面框架)的剪貼簿快捷鍵預設常失靈。新版 VoxLog 已內建修正,但舊的下載版本沒有。

解法:

① 先更新到最新版(見上面「🔄 之後怎麼更新到最新版」,或重新到 GitHub 下載 ZIP 覆蓋),再重開 App 讓修正生效。

② 萬一還是不行,就用不需要貼上的方式填 key —— 照上面 ⑤ 的「🛟 終極解法」直接編 config.json。

⑦ 速度與其他

• Mac 上語音轉錄都跑 CPU:一般 Whisper 與 WhisperX 引擎在 Mac 目前都用 CPU,功能正常但比 Windows + 顯卡慢。(一般 Whisper 因 Apple MPS 缺少它用到的稀疏張量運算、在 MPS 上會崩潰,所以程式自動改用 CPU,不是當機。)

• 想快一點:檔案不大時差異有限;真的很在意速度,Windows + NVIDIA 顯卡才有 CUDA 加速。

• 只想用「載入 .md 做摘要」這類純 AI 功能、不轉錄語音的話,完全不受上面影響,也更快。
