🍎 macOS 安裝指南

好消息:Mac 現在也能像 Windows 一樣「雙擊安裝」了 —— 不用再一行行貼終端機指令。照下面三步,大約幾分鐘就裝好。

0先選一個版本

🪶 輕量版

MacBook Air、記憶體 8GB 的機器。做逐字稿 ＋ AI 摘要,小又快。

install-lite.command

🧰 完整版

要分辨「誰說了哪句」(說話人辨識)才用。多裝約 2GB。

install-full.command
💡 不確定選哪個?只是想把錄音變文字、做會議摘要 → 選輕量版就好。之後想升級成完整版,隨時雙擊 install-full.command 即可,不用重來。

1取得 VoxLog 資料夾

最建議:請對方(Kris)把整包壓縮檔傳給你 → 雙擊解壓縮 → 把 VoxLog 資料夾拖到你想放的地方(例如「文件」)。這種方式之後可以「一鍵更新」。

📁記住 VoxLog 資料夾放哪、別把裡面的檔案拆開搬,整包要待在一起。

(進階)會用 git 的話,打開終端機貼這行 clone 下來(之後更新最順):

git clone https://github.com/Kamiyu94/VoxLog.git

2雙擊安裝檔

打開 VoxLog 資料夾,雙擊你要的那個安裝檔:

🪶 輕量版 → 雙擊 install-lite.command

🧰 完整版 → 雙擊 install-full.command

會跳出一個黑視窗自動安裝(裝 Homebrew、Python、FFmpeg、套件…全自動)。看到「✅ 安裝完成!」就好了,可以關掉視窗。第一次可能要等幾分鐘。

🔐 若雙擊被 macOS 擋住出現「無法打開,因為它來自未識別的開發者」→ 對著那個檔案按右鍵 → 選「打開」→ 再按一次「打開」。只要做這一次,之後就正常。
⏳ 中途「卡住不動」是正常的安裝過程會停在下載畫面好幾分鐘(在抓開發者工具/套件),別關視窗。若彈出 Apple 的「安裝命令列工具」小視窗,按 Install 等它跑完即可。
🔑 需要輸入密碼?安裝 Homebrew 時可能會問這台電腦的登入密碼。輸入時畫面不會顯示任何字(連圓點都沒有),這是正常的,打完按 Enter 就好。

3啟動 VoxLog

安裝完成後,回到 VoxLog 資料夾,雙擊 voxlog 就會打開 App。

⭐ 以後開 VoxLog每次要用,就雙擊資料夾裡的 voxlog。安裝時也順手設好了終端機指令,想的話在任何地方打開終端機打一個字 voxlog 也能開。

4填 API Key 開始用

程式打開後會自動建立設定檔,你不用碰任何檔案。在介面上:

① 選 AI 引擎(ChatGPT / Gemini / Claude)
② 在 Key 欄位貼上 API Key(跟 Kris 拿,或照下面自己申請)
③ 按 「驗證」,變綠就成功(會自動存檔)
④ 載入音檔或 .md / 逐字稿 → 開始轉錄、校正、產生摘要

🗣️ 輕量版看到辨識引擎有些選項是灰的(🔒)?那些(含「說話人辨識」)要完整版才有。要用的話,雙擊資料夾裡的 install-full.command 升級後重開 App 即可 —— App 裡點到時也會跳出同樣的說明。只要逐字稿、不需要分辨誰在說話,維持輕量版、用「whisper.cpp」就好。

怎麼自己申請 Gemini API Key(免費)

Gemini 有免費額度,個人用通常夠。三步:

① 用 Google 帳號登入 Google AI Studio 金鑰頁(網址:aistudio.google.com/apikey)
② 按 Create API key → 選一個專案(沒有就讓它自動建)
③ 產生後按 Copy 複製那串 key,貼進 VoxLog 的 Key 欄位按驗證

❗ 一定要從這個網址拿要的是 Google AI Studio 的 API Key —— 開頭是 AIza 或 AQ. 都正常(AQ. 是 2026 的新格式)。不要拿成 Google Cloud Console「憑證」裡的 OAuth(ya29./GOCSPX-),那種驗證會出現 401 ... Expected OAuth 2 access token 的錯誤。

(想用 ChatGPT 或 Claude 的話,key 分別在 platform.openai.com/api-keys、console.anthropic.com 申請,作法類似。)

✓ 完成! 之後每次要用,雙擊資料夾裡的 voxlog 就能開,不必再重裝。

🔄之後怎麼更新到最新版

VoxLog 有改版時,回到 VoxLog 資料夾,雙擊 update.command 就好。

它會自動抓最新程式碼、判斷你裝的是輕量版還完整版、補裝新套件。你的 API Key 設定和已下載的模型都不會被覆蓋。看到「✅ 更新完成!」就可以雙擊 voxlog 重開。

⚠️ 雙擊 update 說「這不是 git 版本,無法自動更新」?代表你當初是用 GitHub 的「Download ZIP」下載的(那種抓不到更新機制)。最簡單:請 Kris 重給你一份能更新的整包;或改用步驟 1 的 git clone 版本。
(會 git 的話,也可進資料夾後貼下面這段接上線上專案,只做一次;之後 update.command 就能用。)
把「Download ZIP」版本接上 git(進階,只做一次)

進到 VoxLog 資料夾(cd + 拖資料夾),貼這一整段:

git init
git remote add origin https://github.com/Kamiyu94/VoxLog.git
git fetch origin
git reset --hard origin/main
git branch -M main

你的 config.json(API Key)和 venv(環境)都不會被覆蓋。之後更新雙擊 update.command 即可。

⚙手動安裝(進階,或雙擊失敗時)

一般人用上面的雙擊安裝就好,不需要看這段。以下是想自己一步步來、或雙擊安裝失敗時的終端機步驟。

⌨️ 怎麼打開「終端機」?按 ⌘ Command+空白鍵 叫出 Spotlight,輸入 Terminal 或 終端機,按 Enter。
展開手動安裝步驟

① 安裝 Homebrew(套件管家)

先確認有沒有裝過 —— 貼 brew --version。有版本號就跳到 ②;顯示 command not found 就貼:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

裝完(Apple Silicon)要讓系統認得 brew,貼這一整段:

echo >> ~/.zprofile
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

② 裝 Python 與 FFmpeg

brew install python@3.11 python-tk@3.11 ffmpeg whisper-cpp

Mac 系統內建的 Python 太舊,拿來跑 GUI 會一開就閃退,所以一定要用 Homebrew 的 python@3.11。

③ 下載專案

見上面「步驟 1」。用 git clone 或請對方給整包壓縮檔。

④ 建立環境並啟動

先 cd 進 VoxLog 資料夾(cd 加空格,再把資料夾從 Finder 拖進終端機,按 Enter)。然後輕量版貼這段:

/opt/homebrew/bin/python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements-lite.txt
chmod +x voxlog
ln -sf "$PWD/voxlog" /opt/homebrew/bin/voxlog
python transcribe_gui.py

完整版(要說話人辨識)把上面的 requirements-lite.txt 換成 requirements.txt,並照下面 ②③ 疑難排解各跑一次修補。

⚠遇到問題?(疑難排解)

下面幾個是搬到 Mac 第一次安裝才會踩的坑。用雙擊安裝的話,②③ 已經自動幫你處理掉了,通常不會遇到;手動安裝、或真的卡住再對照展開。

① 程式一開就閃退 / SIGABRT最常見

症狀:雙擊 voxlog 後視窗一閃就消失,或報 EXC_CRASH / SIGABRT。

原因:環境被建到了 Mac 系統內建的舊 Python(連到太舊的繪圖元件 Tcl/Tk)。

解法:重跑一次安裝檔(install-lite.command 或 install-full.command)即可 —— 它固定用 Homebrew 的 python@3.11 重建乾淨環境。若要手動:

rm -rf venv
/opt/homebrew/bin/python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements-lite.txt
python transcribe_gui.py
② 連環境都建不起來(pyexpat 符號錯誤)雙擊已自動修

症狀:python3.11 -m venv 失敗,或紅字出現 Symbol not found: _XML_SetAllocTrackerActivationThreshold。

原因:Homebrew 的 Python 內某個模組連到 Mac 系統舊版的 expat 函式庫,缺了新符號。

解法:雙擊安裝檔會自動處理;要手動的話:

brew install expat
SO=$(ls /opt/homebrew/Cellar/python@3.11/*/Frameworks/Python.framework/Versions/3.11/lib/python3.11/lib-dynload/pyexpat.cpython-311-darwin.so | head -1)
install_name_tool -change /usr/lib/libexpat.1.dylib /opt/homebrew/opt/expat/lib/libexpat.1.dylib "$SO"
codesign --force --sign - "$SO"
/opt/homebrew/bin/python3.11 -c "import pyexpat; print('pyexpat OK')"

看到 pyexpat OK 就修好了。⚠️ 日後 brew upgrade 或重裝 python@3.11 後可能要重跑一次(或重跑安裝檔)。

③ 說話人辨識壞掉(torchcodec 找不到 libavutil)雙擊已自動修

症狀:跑「說話人辨識」時報 libtorchcodec... Library not loaded: @rpath/libavutil.59.dylib。(一般轉錄不受影響,只有要分辨不同講者時才會壞。)

原因:系統 FFmpeg 是 8.x,但負責讀音訊的 torchcodec 只吃 FFmpeg 7。

解法:install-full.command 會自動處理;要手動:

brew install ffmpeg@7
cd /opt/homebrew/lib
for lib in libavutil.59 libavcodec.61 libavformat.61 libavdevice.61 \
           libavfilter.10 libswscale.8 libswresample.5; do
  ln -sf "/opt/homebrew/opt/ffmpeg@7/lib/$lib.dylib" "$lib.dylib"
done

之後若看到 objc[...] Class AVFFrameReceiver is implemented in both... 的黃字警告可忽略,不影響 VoxLog。

④ 說話人辨識要怎麼拿 HuggingFace Token?完整版

只有要用「分辨不同講者」時才需要,而且 Token 免費。一般轉錄、做摘要都不用。三步:

① 註冊 / 登入並產生 Token
到 huggingface.co/settings/tokens → 按 Create new token → 名稱隨意,務必勾選 Read access to public gated repositories → 建立後把那串 token 複製起來(只顯示一次)。

② 用同一個帳號到下面兩頁按「同意」
各自進去後點 Agree and access repository:
• pyannote/speaker-diarization-community-1
• pyannote/segmentation-3.0

③ 貼進 VoxLog
打開 App,在「HuggingFace Token」欄位貼上 token(會自動存進 config.json)。

❗ 一定要同意 community-1 那頁VoxLog 實際用的是 speaker-diarization-community-1。填了 token 卻還失敗,多半是只同意了舊版 3.1、漏了 community-1。
⑤ AI 的 API Key 驗證失敗 / 401 錯誤最常見

症狀:在 Key 欄位貼上後按「驗證」,出現紅字 HTTP 401: ... Expected OAuth 2 access token ...,或一直不會變綠。

原因 1:拿錯 key。Gemini 的 API Key 兩種開頭都合法:AIza(舊格式)或 AQ.(2026 新格式,VoxLog 也支援)。但如果 key 是 ya29.、GOCSPX-、4/ 開頭,那不是 API Key,複製錯地方了。一律到 aistudio.google.com/apikey 拿。

❗「瀏覽器跑出東西」不等於 key 是好的壞 key 一樣會回一段 JSON。要看內容:
• 一條條 "models/gemini-..." 清單 → key 好
• 開頭是 "error"、有 "API key not valid" 或 code: 400/401/403 → key 壞(換一把)

測試網址(把「你的KEY」換掉,貼瀏覽器按 Enter):

https://generativelanguage.googleapis.com/v1beta/models?key=你的KEY

原因 2:key 沒貼乾淨。Key 欄位用星號遮住;若欄位裡有殘缺的舊 key、又沒清掉就貼,新 key 會接在後面變壞。解法:點進欄位 → 整個刪乾淨 → 再貼一次乾淨的 key。

🛟 終極解法:直接寫進設定檔如果都試了還失敗,在 VoxLog 資料夾內開設定檔: 
open -e config.json
把 "gemini_key": "..." 引號中間整段換成確認過的 key(其他引擎是 anthropic_key / openai_key),存檔(⌘S)→ 重開 voxlog。
⑥ App 裡複製貼上(⌘C / ⌘V)沒反應macOS

症狀:在 VoxLog 視窗裡 ⌘C / ⌘V / ⌘A 沒作用。

原因:Mac 上 tkinter(介面框架)的剪貼簿快捷鍵預設常失靈。新版已內建修正,舊下載版本沒有。

解法:① 先雙擊 update.command 更新再重開 App。② 還不行就用不需貼上的方式填 key —— 照 ⑤ 的「🛟 終極解法」直接編 config.json。

⑦ 速度與其他

• Mac 上語音轉錄都跑 CPU:Whisper 與 WhisperX 在 Mac 目前都用 CPU,功能正常但比 Windows + 顯卡慢。(Apple MPS 缺少 Whisper 用到的稀疏運算會崩潰,所以程式自動改用 CPU,不是當機。)

• 真的很在意速度,Windows + NVIDIA 顯卡才有 CUDA 加速。

• 只用「載入 .md 做摘要」這類純 AI 功能、不轉錄語音的話,完全不受影響,也更快。
